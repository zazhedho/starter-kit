# Media module

Authenticated file upload to object storage (MinIO or Cloudflare R2) with metadata in PostgreSQL, a paginated
list, and owner-controlled deletion. It is the reference for the ownership convention in
[`docs/adding-a-module.md`](../adding-a-module.md#ownership-and-the-_any-permissions).

- Code: `internal/{domain,dto,services,repositories}/media`, `internal/handlers/http/media`,
  `internal/router/media` (`wire.go`, `register.go`, `storage_adapter.go`), `internal/infrastructure/storage`,
  `internal/config/media.go`.
- Off by default: nothing is mounted unless `MEDIA_ENABLED=true`, and the storage provider is only opened
  then.

## Routes

Mounted under `/api` only when `MEDIA_ENABLED=true`. The list in `internal/router/media/routes_test.go` is
the source of truth.

| Method | Path | Auth | Notes |
|---|---|---|---|
| GET | `/api/media` | token; `Auth()` then `LoadPermissions()` | your own files, or everyone's with `media:list_any`; paginated, see below |
| POST | `/api/media` | token (any authenticated user, no extra permission) | multipart form field `file`; `201` with the stored metadata; `400` for a missing, empty or unsupported file; `413` over the size limit; `429` over the per-IP or per-user upload limit (both need Redis) |
| DELETE | `/api/media/:id` | token; `Auth()` then `LoadPermissions()` | your own file, or anyone's with `media:delete_any`; `:id` must be a UUID; `200`; `404` when the media does not exist or belongs to someone else without `delete_any` (the response does not reveal which, and storage is left untouched; a row removed by a concurrent delete also answers `404`) |

### Permissions

| Permission | Seeded to | Grants |
|---|---|---|
| `media:list_any` | `admin`, `superadmin` | list other users' files |
| `media:delete_any` | `admin`, `superadmin` | delete other users' files |

Acting on your own files needs no permission. `superadmin` passes every check. The handler reads the
permissions with `authkit.ScopeFrom(ctx).Has("media", "list_any")` after `LoadPermissions()` and hands the
service a `domainmedia.Actor`; the service never imports authkit. The migration seeds both permissions in
`migrations/20260101000100_media_create_table.up.sql`.

### List query parameters

| Parameter | Default | Meaning |
|---|---|---|
| `page` | `1` | page number; a value below 1 becomes 1; a non-number answers `400` |
| `limit` | `20` | page size, at most `100`; missing, `0` or negative falls back to 20, above 100 and `-1` become 100 (one cap, gokit's `QueryOptions.MaxLimit` in the repository; "every row" is never allowed); a non-number answers `400`; the response `limit` is the size actually applied |
| `search` | empty | file name contains the text, case-insensitive; `%` and `_` in the text act as LIKE wildcards |
| `order_by` | `created_at` | `created_at`, `size` or `original_name`; any other column, or an `order_direction` that is not `asc`/`desc` or is missing, falls back to `created_at` `desc` |
| `order_direction` | `desc` | `asc` or `desc` (see `order_by` for the fallback); rows with equal values are ordered by `id` in the same direction, so pages never skip or repeat rows |
| `filters[content_type]` | empty | exact content type |
| `filters[owner_user_id]` | empty | exact owner UUID; honored only with `media:list_any` (then `400` when it is not a UUID); without it the value is ignored and replaced with your own id |

Any other `filters[...]` key is ignored. The response is gokit's paginated envelope (`total_data`,
`total_pages`, `current_page`, `next_page`, `prev_page`, `limit`, `data`; `data` is `[]` for an empty page). Soft-deleted files are never listed.

Upload and delete write an audit entry (resource `media`, action create or delete) on success and on failure.
Object names are generated by the server (`media/<UTC timestamp>_<random UUID>.<extension>`), so a URL cannot be
guessed. The client's file name is reduced to its base name, stripped of control characters and invalid UTF-8,
capped at 255 characters and replaced by `file` when nothing is left, before it is stored as `original_name`.

## Environment variables

| Variable | Default | Meaning |
|---|---|---|
| `MEDIA_ENABLED` | `false` | mount the media routes and open storage |
| `MEDIA_MAX_FILE_SIZE_MB` | `5` | largest accepted file, 1-1024 MB |
| `MEDIA_ALLOWED_CONTENT_TYPES` | `image/jpeg,image/png,image/webp,image/gif,application/pdf` | comma-separated accepted types; each must be one of those five (the sniffer can match them and the service has an extension for them), anything else, `text/html` and SVG included, stops the service at startup |
| `MEDIA_UPLOAD_TIMEOUT` | `2m` | read and write deadline for one upload request, replacing `HTTP_READ_TIMEOUT` and `HTTP_WRITE_TIMEOUT` for that route; the write deadline is extended too so the response of a slow upload is delivered instead of cut off |
| `MEDIA_UPLOAD_RATE_LIMIT` | `20` | uploads allowed per client IP per window; must be above zero when media is enabled |
| `MEDIA_UPLOAD_RATE_WINDOW_SECONDS` | `60` | rate-limit window in seconds; must be above zero when media is enabled |
| `MEDIA_UPLOAD_USER_RATE_LIMIT` | `10` | uploads allowed per authenticated user per window, whatever the IP; must be above zero when media is enabled |
| `MEDIA_UPLOAD_USER_RATE_WINDOW_SECONDS` | `60` | window of the per-user limit in seconds; must be above zero when media is enabled |
| `STORAGE_PROVIDER` | `minio` | `minio`, `r2`, `cloudflare` or `cloudflare-r2` |
| `STORAGE_ENDPOINT` | empty | storage endpoint, required |
| `STORAGE_ACCESS_KEY` | empty | required |
| `STORAGE_SECRET_KEY` | empty | required; never printed in logs |
| `STORAGE_BUCKET_NAME` | empty | required |
| `STORAGE_BASE_URL` | empty | public base URL of the bucket, required when media is enabled, must be a valid URL |
| `STORAGE_USE_SSL` | `false` | use TLS to reach the endpoint; must be `true` for the R2 providers, which would otherwise send the secret key in clear text |
| `STORAGE_REGION` | `auto` for R2, empty for MinIO | region the requests are signed for; leave it empty for MinIO unless you changed the server's region |
| `STORAGE_PUBLIC_READ` | `false` | MinIO only: give a bucket this service creates an anonymous read policy |
| `R2_ACCOUNT_ID` | empty | Cloudflare account id, for the R2 provider |

Storage settings are also validated when any of them is set while media is disabled: the endpoint, both keys
and the bucket must then all be present.

## Table

`migrations/20260101000100_media_create_table.up.sql` creates `media`: `id`, `owner_user_id` (foreign key to
`users`, `ON DELETE RESTRICT`), `object_key` (unique; the name the object has in the bucket, used to delete it),
`url`, `original_name`, `content_type`, `size` (greater than zero), `created_at`, `deleted_at` (soft delete:
deleting a media marks the row, it does not remove it). The index
`idx_media_owner_created_at (owner_user_id, created_at DESC, id DESC)` serves the default list of your own files in
the list's order, including its `id` tie-breaker.

## Operational notes

### Storage requirements

- Enabling media requires a reachable storage provider with valid credentials and an explicit
  `STORAGE_BASE_URL`. At startup both providers check, within 15 seconds, that the bucket exists and create it when
  it is missing, so the credentials need permission to create buckets for a first start. A provider that cannot
  start is a startup failure (exit code 1).
- A bucket the service creates is private. With `STORAGE_PUBLIC_READ=true` the MinIO provider gives a bucket it
  creates an anonymous read policy; a bucket that already exists is never changed. R2 has no bucket policy: expose
  an R2 bucket through a custom domain or `r2.dev` in Cloudflare.
- The `url` in an upload response is `STORAGE_BASE_URL` plus the object name. It works without signing only when
  the bucket is public. For a private bucket, serve files through presigned URLs: add a method that calls the
  S3 client's `PresignedGetObject(ctx, bucket, objectKey, expiry, nil)` to the provider, build the link from the
  row's `object_key` when a user asks for the file, and let the link expire. Presigning needs no extra
  configuration; it uses the same credentials.
- The module checks that storage was handed to it; if it is missing the error is
  `register media routes: storage is required when media is enabled`.

### Limits

- `HTTP_MAX_BODY_MB` (default `10`) must be larger than `MEDIA_MAX_FILE_SIZE_MB`; configuration validation
  fails otherwise when media is enabled.
- The upload route reads at most the file limit plus 1 MiB of multipart overhead; anything beyond answers `413`.
- The content type is detected from the first 512 bytes of the file. The client's extension and `Content-Type`
  header are not trusted, and nothing after those bytes is inspected, so a file can start like an image and carry
  other content later: serve uploads from a separate origin or with `Content-Disposition: attachment`. SVG and
  HTML can never be allowed.
- Rate limiting needs Redis: one limit per client IP and one per user. Without Redis the upload route has no
  rate limit and a warning is logged at startup.

### Failure behavior

- If saving the metadata row fails after the object was stored, the object is deleted again, even when the
  client has gone away: the removal has its own 10 second deadline. A failed removal is logged at error level with
  the object name, so the orphan can be cleaned up.
- Deleting removes the object named by the row's `object_key` first, then marks the row deleted; if the object
  cannot be deleted the row stays active. Changing `STORAGE_BASE_URL` or the bucket's public address does not
  affect deletion.
